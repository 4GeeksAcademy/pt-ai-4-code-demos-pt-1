## Decisions Made

1. **FastAPI migration is the right call** — The existing `BaseHTTPRequestHandler` with regex parsing is fragile and unmaintainable. FastAPI gives automatic Pydantic validation, structured errors, OpenAPI docs, CORS, and a testable client. Cold start overhead is negligible (~50-100ms) compared to image generation time (~200-500ms).
2. **Tests first, then migration** — Step 03 (unit tests) must be completed before Step 04 (FastAPI migration). The FastAPI step itself requires writing tests *before* deleting the old handler.
3. **Modular rules over monolithic** — Each safety concern gets its own file, making rules easy to reference, update, or suppress per-task.
4. **Input validation subsumed by FastAPI** — No need for a separate "add input validation" step since Pydantic models built into the FastAPI migration handle that automatically.
